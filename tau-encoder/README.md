# Tau Encoder

A Tauri + Svelte desktop preview using the reusable `tau-video` Rust crate. Choose a video source and destination folder. The C reference encoder is the default, with suffix `_C`; edit the suffix to distinguish your files. A build with `--features experimental-rust-encoder` exposes the parked Rust encoder with suffix `_R`. Each encode produces one `.tnv3` file with the audio stored inside it as TAC (the MP3 sidecar is parked; the legacy path remains in the code for an explicit `audio: "mp3"` setting but the app no longer offers it) and remembers the output folder. Existing files are never overwritten.

When the optional Rust encoder is enabled, both options share ingest and sidecar settings, but their compression decisions are not yet equivalent. C is the more developed reference encoder; Rust remains preliminary. See `docs/RUST_C_ENCODER_PARITY.md` in the repository.

The C option defaults to the "Rust + C (no Python)" workflow since 2026-11-08; "Python + C (reference)" is the segmented workflow (`tools/tnv3_ref/encode_film.py`), with video-only output and aspect-preserving scaling at 24 fps. Python 3 must be installed and available as `python3` on macOS/Linux or `python` on Windows; set `TAU_PYTHON` to an interpreter if needed. The "Rust + C (no Python)" workflow (Rust orchestration around the same C encoder, byte-identical output in the comparisons made, stoppable) is the default and Python + C stays selectable; it runs the same C video encoder and does not change audio encoding (FFmpeg converts the audio, then the C `tac` encoder at 96 kbit/s, then the C `tnv3 mux` joins it; this step needs `tnv3` and `tac`, can be stopped, and was run in tests only with short clips). It avoids the Python dependency and tracks a projected temporary workspace budget (default 512 MiB); long films may need a higher user-set budget. Actual disk use may vary from the projection. Both workflows require enough temporary disk space for their processing. The separate experimental Rust encoder mode remains unchanged and does not use this workflow selector.

When the source has text subtitle tracks, a **Subtitles** menu lets you draw one into the file (subtitles are drawn by the built-in Rust builder with no Python; Settings needs a subtitle font, a `.ttf` file, unless `TAU_SUBTITLE_FONT` is set). Subtitles are read as ASS, so styles, colours and italics are kept (positions are ignored). Image subtitles cannot be used. When the source has several audio tracks, an **Audio track** menu picks the one to encode.

The preview shows the file's subtitles when it has any: the output window is 800×720 with the picture centred (as the reference renderer and the builder assume), and a menu picks on/off (off shows only forced lines), track, size, and whether sound descriptions are hidden. It draws the baked outline and the palette colours from the Rust reader and follows the audio clock. Delay, vertical offset and box settings are not implemented, and the native window was not driven in the checks below. Local preview opens a TNV3, plays its embedded TAC audio (decoded to a temporary WAV with the C `tnv3` and `tac_fx` (integer decoder) tools when the file is opened, a few seconds for a 28 minute episode) or a matching MP3 if present. The embedded-audio playback path was built but not run in the app UI. It decodes the video on the host, supports play/pause and drops late video frames against the audio clock. It is for visual checks, not a Pocket performance emulator or a full conformance checker. Seeking and replay without reopening are not implemented; the preview has not been validated on all platforms.

The app currently requires a source audio track. Output is 24 fps and 48 kHz stereo TAC audio inside the `.tnv3`; the Rust encoder uses conservative rate control and may fail or reduce quality. The Python workflow reports segment progress; the native C workflow reports completed segments and updates its video-time estimate. Audio and saving are separate. Pocket A/V synchronisation remains to be validated.

## Platform status

The macOS Apple Silicon archive includes FFmpeg 9.0.2, FFprobe and the C tools. Python 3 remains separate for the default workflow. The macOS app is ad-hoc signed and not notarized.

Closing the window or quitting during an encode asks first ("Keep encoding" or "Stop and quit"; stopping ends the encode's tools and saves no file); a `kill` or a closed terminal stops the encode cleanly before the app exits, while a force quit (SIGKILL) cannot be intercepted and simply ends the app. Every encode writes a detailed log (one JSON-lines file in the app's log folder, `~/Library/Logs/dev.tau.encoder` on macOS: settings, tools and versions, source, progress every second, phase times, warnings, result or error); Settings has the on/off switch (default on) and an "Open log folder" button. Subtitles are drawn at four large sizes (32×44, 40×54, 48×64, 56×76, outline 2, 3, 3, 4; the Pocket's own choice after the first small sizes were too small to read), in the bottom bar; the player menu defaults to the third size. On macOS the Dock icon shows the encode progress as an amber bar drawn on the icon (video three quarters, audio one eighth, subtitles one eighth; audio and subtitles shimmer while they run, the bar turns green when done and red on failure); Windows and Linux use the system progress bar. Windows and Linux executable-only builds are **not runtime-tested**, are not installers, and do not bundle dependencies. Install FFmpeg and FFprobe with libmp3lame, Python 3 for the Python workflow, and matching `encode_film.py`, `tvc_enc` and `tnv3` tools separately. Configure their full paths in Settings; the Python-free workflow needs FFmpeg and both C tools. The operating system also needs the Tauri runtime (WebView2 on Windows; WebKitGTK and other Tauri libraries on Linux). A CI build is not a runtime or Pocket playback test.

## Dependency settings

Open **Settings** to inspect automatically detected paths, choose a detected installation, refresh the scan, or browse to or enter full paths for FFmpeg, FFprobe, Python 3, `encode_film.py`, `tvc_enc`, `tnv3` and `tac` (use the `.exe` programs on Windows). The Python workflow uses these tools; the native C workflow uses FFmpeg and the two C tools without Python or the script. Selected paths override automatic discovery and are remembered on this computer. Clear a field to return to the bundled, environment or default tool. If FFprobe is blank, the app looks beside the selected or automatically discovered FFmpeg. A selected file must exist; executable permissions and compatibility with the current platform are still required. FFmpeg must support the source formats and `libmp3lame`.

These controls do not themselves bundle dependencies or establish Windows/Linux runtime compatibility. The Python script and C programs should come from a matching Tau codecs build. Test a short encode after configuring them.

## Advanced Pocket experiments

The C encoder and the optional experimental Rust encoder share these optional ingest/audio controls. Defaults remain unchanged. For a meaningful comparison, use the same source and encoder, change one option at a time, and choose a distinct suffix for each output pair. Test the full video and listen for synchronization on Pocket.

- **Round frame timestamps down** may avoid repeated frames with some source timestamps. Generated tests also showed a missing final frame and a one-frame shift with variable-rate input.
- **Pass the final frame with round-down** can restore a missing frame but produced an additional frame in other cases. It only applies when round-down is enabled.
- (Removed from the app: **Test MP3 delay compensation**, which only applied to the MP3 sidecar.) It removed the first 1,105 samples (about 23 ms) of source audio before MP3 encoding. This permanently discards that audio and may make sync better or worse. The amount comes from an FFmpeg host model, not a Helix or Pocket measurement. Do not assume it corrects hardware synchronization.

Source decoding diagnostics remain enabled; they cannot detect every corrupt source. These options do not repair the unresolved Pocket frame freeze, change the player, or make the Rust and C encoder implementations equivalent. See `docs/issues/003-rust-encoder-player-throughput.md`, `005-hevc-input-ingest.md`, and `006-mp3-gapless-timing.md` in the repository.

## Development

Install Node.js, Rust and the Tauri v2 platform prerequisites. From this directory run `npm ci`, then `cargo install tauri-cli --version '^2' --locked`, compile the C tools with `make` in the repository root, and run `cargo tauri dev`. FFmpeg and FFprobe are used by the app; set `TAU_FFMPEG` or install them on PATH if a bundled copy is absent.

For a self-contained macOS helper bundle, run `scripts/build-ffmpeg-macos.sh`, then `scripts/build-codec-tools.sh`, then `cargo tauri build --config src-tauri/tauri.bundle.conf.json`. This includes the C tools and LGPL FFmpeg 9.0.2 dynamically linked to LGPL LAME 4.0, with corresponding sources, licenses and build instructions. Python remains a separate dependency. Equivalent bundled helpers and platform validation on Windows and Linux remain outstanding.

## App versioning

The desktop app follows semantic versioning independently of the codec format and Rust crate. Version 0.9.0 is a preview: increment the patch for compatible fixes, the minor for new functionality or breaking changes before 1.0, and the major for breaking changes after 1.0. Prereleases use a SemVer suffix such as `-alpha.1`. Update the npm, Tauri, Cargo and lockfile versions together; `npm run check-version` checks their agreement in CI. Name distributed builds `Tau-Encoder-<version>-<platform>` and document changes in the changelog.

## Resolution and levels

Choose a width of 240, 360, 400, or 800 pixels, or enter a custom even width up to 800. Height follows the source aspect ratio; very tall sources scale down as needed to stay within 720 pixels. The app inspects the actual dimensions and shows the lowest compatible level. Both C workflows support automatic or explicit levels 1–3; an incompatible explicit level fails. The experimental pure Rust encoder selects its level automatically. The C encoder may increase picture QP to satisfy level limits, reducing quality, and fails if a valid stream cannot be produced. Pocket playback at higher levels and resolutions is not verified. The local player displays video at 1× by default and offers 2× and 4× scales.

## Source errors and stopping

Unless **Always continue when source errors are found** is enabled in Settings, the native Rust+C workflow asks during video or audio processing when FFmpeg reports an error. The decision applies to the rest of the job; the dialog can save the continue preference for future jobs. Diagnostics remain visible in the result, and a fatal process error still fails the encode. This feature does not repair or certify source data.

The native workflow requests termination and reaping of its directly owned FFmpeg, C encoder and container-tool processes. It stages both files and rejects Stop once final saving has begun. This assumes those executables are leaf processes: custom tools that launch descendants and unexpected supervisor termination are not fully contained. If cleanup cannot be verified, the app reports that instead of claiming a clean stop; temporary files may be retained. A crash or card removal during saving can still leave a partial pair.

The Python workflow retains its full source preflight when the preference is off. The check can take as long as decoding the source and can be stopped. Later warnings are presented at phase boundaries, and Stop waits for the current phase. See `docs/issues/009-c-encoder-process-cancellation.md` and `docs/issues/012-source-error-preflight.md`. Windows and Linux runtime behaviour remains untested.
