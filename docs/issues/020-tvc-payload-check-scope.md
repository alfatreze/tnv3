# 020 — TVC decode success is not full payload validation

2026-11-07. An isolated `tvc-payload` checker prototype in `work/cli-full-check-new` sent TNV3 pictures through the Rust decoder and rejected a mutated TVC header with recomputed chunk CRC. Independent **code-review** found that the prototype opened files without the preview's nonblocking regular-file checks, classified every error as invalid even for I/O/limits/unsupported features, and gave no reliable error offset. The current decoder reads indexed pictures but does not replace the container cross-frame/subtitle/audio checks; its range decoder zero-pads exhausted slices and cannot establish canonical payload validity from decode success. Per-picture limits exist, but overall CPU time, OOM and malformed-input panic safety are not established. **Host:** targeted prototype tests only; no Pocket claim. Impact: the prototype cannot honestly be promoted to full payload conformance or report all decoder failures as invalid. Workaround: retain existing explicitly scoped checks and independent reference tooling; do not expose this prototype. Next: type invalid/unsupported/I/O/limit errors with offsets, use safe input opening, define complete decoder/conformance coverage and bounds, and validate negative vectors before adding the scope.

Later 2026-11-07: an isolated typed-error draft in `work/tvc-decode-errors-new` passed tests but independent review found it would break exhaustive matches on the existing public `StreamError`, report imprecise header offsets, and classify level 4 as unsupported even though TVC spec section 8 defines it as invalid. Review also found the existing stream decoder ignores TVC1's three reserved header bytes. The draft is not integrated; preserve the existing API and correct field-level classification in a separate opt-in interface before reconsidering it.

Later 2026-11-07: the crate now offers an opt-in detailed elementary-stream error API with field offsets, ambiguous picture failures, separate I/O and decoder limits. The original exhaustive error enum remains; its wrapper now rejects nonzero TVC1 reserved bytes previously accepted, and error message text may differ. Review confirmed levels 1–3 were already enforced. Successful decode still does not establish full payload conformance or enforce every declared level limit; the withheld CLI scope remains unsupported.
