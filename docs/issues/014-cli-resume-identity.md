# 014: Resume identity must bind immutable input and artifacts

Date: 2026-11-06. Status: open. Evidence: **code-review** and prototype **host** unit tests; no Windows/Linux or Pocket validation.

The CLI contract requires byte-identical restart from finished segments. The initial isolated prototype in `work/cli-resume-identity/` hashes source and tool paths and compares a bounded JSON identity. Independent review found path metadata could race file replacement, named executable roles and output-affecting settings were not required, non-UTF-8 paths could be represented lossily, and comparing manifests did not authenticate reused segment artifacts. Same-size concurrent source edits can evade metadata checks. A matching prototype identity is therefore not sufficient to reuse any work.

Expected: bind an immutable source snapshot and actual executed tools/settings to a protected workspace, verify each reusable artifact against an authenticated checkpoint, and reject incomplete or changed inputs. Impact: deterministic `--work` resume remains unavailable; blindly reusing a prototype manifest could produce incorrect output. Workaround: use the existing fresh-encode workflow. Next: strengthen descriptor-based identity and required roles, then implement artifact verification, checkpoint lifecycle and interruption/failure tests as recorded in Tau codecs `docs/RESUMABLE_CLI_DESIGN.md`. Do not claim mutation safety from metadata alone.

## 2026-11-06 anchored-workspace prototype

**Host:** An isolated prototype now checks aggregate artifact bounds, walks Unix workspace paths with descriptor-relative no-follow opens, validates user ownership/modes, and hashes opened artifact descriptors. It can create an initial checkpoint through exclusive temp creation, file sync, no-replace rename and directory sync; updates to existing checkpoints remain unsupported. Twenty prototype tests passed on macOS, and Windows cross-compilation passed with workspace operations explicitly unsupported. This does not establish authenticated checkpoint reuse, parsed-segment/rate-tail semantics, immutable source/tool snapshots, crash recovery, full invocation identity or a functioning `--work` workflow. Independent review is pending. No production resume was enabled.

**Code-review update:** Owner and Unix mode-bit checks do not establish that extended ACLs deny access to other users; do not describe the workspace as proven private until ACL behavior is verified or the claim is narrowed. The initial writer also needs an explicit empty-checkpoint policy or artifact-verification prerequisite. These do not enable resume and are being corrected in the isolated prototype.

## 2026-11-06 cooperative checkpoint-update prototype

**Host / code-review:** The isolated prototype now supports nonblocking advisory-lock checkpoint replacement, expected-digest and append-only checks, artifact hashing, and explicit post-rename durability uncertainty. Review found and prompted correction of lock-file creation in a foreign workspace; the revised preflight rejects existing foreign entries without creating the lock. Twenty-nine tests passed on macOS, including contention, stale data and fault injection; Windows cross-compilation passed with workspace operations unsupported. These guarantees apply only to cooperating writers. ACLs are not checked, artifact data must be synced by its producer, and noncooperating same-user mutation, segment syntax/rate-tail validation, immutable input/tool snapshots and real restart parity remain unsolved. Resume is not enabled.
