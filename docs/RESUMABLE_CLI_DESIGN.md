# Deterministic CLI resume design

Status: proposed, 2026-11-06. This is not implemented or a claim that resume is available.

## Decision and alternatives

Introduce opt-in `--work DIR` for the native C orchestration path while retaining the existing ephemeral workflow. Preserve accepted segments and a versioned manifest in a private, exclusively owned job workspace. The alternative of seeking directly into arbitrary source media on restart is deferred because codec seeking, frame reordering, timestamps and damaged inputs can produce different decoded frames. The conservative first implementation decodes from the beginning and hashes each regenerated Y4M group before reusing its accepted segment; this saves C encoding work but not source decoding time.

## Identity and checkpoints

Before reuse, bind the workspace to a full source SHA-256, requested and resolved settings, profile and schema versions, segment geometry and source frame header, plus hashes of FFmpeg and the C helpers and their relevant arguments. A changed, unreadable or unverifiable identity refuses reuse rather than guessing. Include platform and environment inputs if they can change the generated bytes; otherwise do not claim cross-platform byte determinism.

Accept a segment only when its input is complete, its C worker has finished and been reaped, the resulting TVC parses and has the expected frame count, any boundary retry has completed, and the resulting rate-window state has been validated. Boundary repair makes a segment dependent on the previous accepted tail: persist and verify sufficient preceding picture-size/window state and final post-retry bytes. Hash and sync the accepted artifact before atomically replacing and syncing a versioned checkpoint. Recovery validates every referenced artifact and rebuilds the merged TVC; an uncommitted or torn checkpoint is never authoritative. Do not delete unknown or user-owned files from a supplied directory.

Restart mux and final checks as a separate phase; compare resumed output byte-for-byte to uninterrupted output. The existing no-replace publication remains: a partial pair may exist after a publish failure and must be reported without overwriting or deleting either output. Two output names are not atomically committed. Resume cannot automatically repair a partially published pair by overwriting it.

## Validation gate

Use generated fixtures and fake tools to interrupt before and after segment completion, artifact sync, checkpoint replace, boundary retry, merge, mux and publication. Confirm identical final bytes after each accepted checkpoint, reject changed source bytes, options, tools, manifests and damaged/truncated artifacts, and exercise duplicate/foreign workspace contents. Test short writes and failed sync/rename, input decoding errors and cancellation while a worker is active. Run long-source and real-tool tests, then Windows and Linux runtime tests before platform support claims. The full container checker, safe process ownership, separate audio publication and Pocket playback remain independent gates.
